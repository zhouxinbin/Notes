# 服务器通过 SSH 反向端口转发使用本机 Clash Verge 代理

本文实现的效果是：服务器（例如 GPU 服务器）经由 SSH 隧道，使用本地电脑上 Clash Verge 的代理访问互联网。

适用场景：

- 本地电脑：macOS 或 Windows，运行 Clash Verge；
- 远程端：Linux 服务器；
- 连接方式：VS Code Remote - SSH；
- 本地代理端口示例：`7897`；
- 服务器侧代理端口示例：`17897`。

> `17897` 仅监听在服务器的 `127.0.0.1`，只有当前服务器能使用，默认不会暴露给局域网或公网。

## 原理

```text
服务器上的程序
   │  HTTP(S) 代理：127.0.0.1:17897
   ▼
服务器 SSHD 监听的 17897
   │
   │ SSH RemoteForward（反向端口转发）
   ▼
本地电脑的 127.0.0.1:7897
   │
   ▼
Clash Verge → Internet
```

`RemoteForward 17897 127.0.0.1:7897` 的含义：**服务器的 `17897` 端口收到连接后，通过 SSH 隧道转到本机的 `7897` 端口。**

## 一、先确认 Clash Verge 的本地代理端口

1. 打开 Clash Verge。
2. 确保已启用代理，并已选择一个可用节点。
3. 在 Clash Verge 的设置或端口设置中查看端口。常见配置如下：

   - Mixed Port：`7897`（通常同时支持 HTTP 和 SOCKS5）；
   - HTTP Port：例如 `7890`；
   - SOCKS Port：例如 `7891`。

本文用 `7897` 举例；如果你的实际端口不同，请将后文所有 `7897` 替换为实际端口。

在本地终端验证 Clash Verge 代理。macOS：

```bash
curl -I -x http://127.0.0.1:7897 https://www.google.com
```

Windows PowerShell：

```powershell
curl.exe -I -x http://127.0.0.1:7897 https://www.google.com
```

应看到 HTTP 响应头（例如 `HTTP/2 200` 或 `HTTP/1.1 200 Connection established`）。若这里失败，先检查 Clash Verge 的节点、代理模式和端口。

## 二、配置 SSH 反向端口转发

### macOS

编辑 SSH 配置文件：

```bash
mkdir -p ~/.ssh
nano ~/.ssh/config
```

添加或修改服务器条目：

```sshconfig
Host qiao-gpu
  HostName your-server.example.com
  User your-server-user
  RemoteForward 17897 127.0.0.1:7897
  ExitOnForwardFailure yes
  ServerAliveInterval 30
  ServerAliveCountMax 3
```

如果连接的是另一台服务器，添加另一个条目即可：

```sshconfig
Host gpu-2
  HostName another-server.example.com
  User your-server-user
  RemoteForward 17897 127.0.0.1:7897
  ExitOnForwardFailure yes
  ServerAliveInterval 30
  ServerAliveCountMax 3
```

建议限制配置文件权限：

```bash
chmod 600 ~/.ssh/config
```

### Windows

使用 Windows 自带 OpenSSH 时，编辑：

```text
C:\\Users\\你的Windows用户名\\.ssh\\config
```

例如：

```sshconfig
Host qiao-gpu
  HostName your-server.example.com
  User your-server-user
  RemoteForward 17897 127.0.0.1:7897
  ExitOnForwardFailure yes
  ServerAliveInterval 30
  ServerAliveCountMax 3
```

在 PowerShell 中可用以下方式打开文件：

```powershell
notepad $env:USERPROFILE\.ssh\config
```

如果使用 Git for Windows 自带的 SSH，请确认 VS Code 实际使用的 SSH 配置路径；通常仍建议统一使用上述 `%USERPROFILE%\\.ssh\\config`。

## 三、在 VS Code Remote - SSH 中使用

1. 完成上面的 SSH 配置后，打开 VS Code。
2. 按 `F1`，选择 **Remote-SSH: Connect to Host...**。
3. 选择 `qiao-gpu`，不要直接手动输入 `用户名@服务器地址`。
4. 正常连接并打开服务器目录。

VS Code 会读取该 SSH Host 条目并建立反向端口转发。每次 Remote-SSH 重连后，转发也会重新建立。

### 手工验证 SSH 配置

如果想先不通过 VS Code 排查，可在本地终端执行：

```bash
ssh -v -N qiao-gpu
```

保持窗口打开。输出中应包含类似下面的成功信息：

```text
remote forward success for: listen 17897, connect 127.0.0.1:7897
```

按 `Ctrl+C` 结束测试；随后可改用 VS Code 连接。

## 四、在服务器上启用代理

连接到服务器后，先确认反向端口正在监听：

```bash
ss -lnt | grep 17897
```

预期结果类似：

```text
LISTEN 0 128 127.0.0.1:17897 0.0.0.0:*
```

测试 HTTP 代理：

```bash
curl -I -x http://127.0.0.1:17897 https://www.google.com
```

如果 Clash Verge 的 `7897` 是 Mixed Port，也可以测试 SOCKS5：

```bash
curl -I -x socks5h://127.0.0.1:17897 https://www.google.com
```

确认成功后，按照第五节将代理变量写入 `~/.bashrc`；然后直接验证：

```bash
curl -I https://www.google.com
```

## 五、让服务器每次登录自动设置代理

在服务器的 `~/.bashrc` 末尾添加以下内容：

```bash
export http_proxy=http://127.0.0.1:17897
export https_proxy=http://127.0.0.1:17897
export HTTP_PROXY=$http_proxy
export HTTPS_PROXY=$https_proxy
```

保存后重新登录服务器，或执行：

```bash
source ~/.bashrc
```

> SSH/VS Code 会话尚未建立反向转发时，这些变量仍会存在，但网络请求会失败；重新连接后转发恢复即可。

如需临时关闭代理：

```bash
unset http_proxy https_proxy HTTP_PROXY HTTPS_PROXY
```

## 六、常见问题

### `ping google.com` 丢包，是不是代理没有生效？

不一定。`ping` 使用 ICMP 协议，不支持 HTTP/SOCKS 代理，不会经过 `http_proxy` 或 `https_proxy`。请用 `curl`、`git`、`pip` 等支持代理的工具测试。

### 服务器能看到 `17897` 在监听，但 `curl` 失败

优先检查本机 Clash Verge：

- Clash Verge 是否正在运行；
- 节点是否可用；
- `7897` 是否为正确的端口；
- 本机 `curl -x http://127.0.0.1:7897 ...` 是否能成功。

也可在服务器运行：

```bash
curl -v -x http://127.0.0.1:17897 https://www.google.com
```

### SSH 提示 `remote port forwarding failed for listen port 17897`

常见原因：

1. 服务器上已有另一条 SSH 会话占用了 `17897`；换一个端口，例如 `17898`。
2. 服务器的 SSH 服务禁止 TCP 转发；需管理员在服务器的 `sshd_config` 中允许 `AllowTcpForwarding yes`。
3. 使用 `ExitOnForwardFailure yes` 后连接立即退出；这是预期保护，表示转发没有成功建立。

### VS Code 已连接，但端口没有监听

确认你是从 **Remote-SSH: Connect to Host...** 选择了配置中的 Host 别名（如 `qiao-gpu`）。若直接连接 IP，可能没有使用含 `RemoteForward` 的配置。也可在 VS Code 的 Remote-SSH 日志中查看实际执行的 SSH 命令。

### `pip`、`conda`、`git` 是否会自动使用？

多数命令行工具会读取 `http_proxy` / `https_proxy`。可分别测试：

```bash
git ls-remote https://github.com/git/git.git HEAD
pip index versions pip
```

部分工具（特别是 conda、Docker、系统服务）可能有自己的代理设置，需单独配置。

## 安全说明

- 保持默认写法 `RemoteForward 17897 127.0.0.1:7897`，不要无必要地把服务器监听地址改为 `0.0.0.0`。
- 不要在服务器上设置永久的明文代理账号密码。
- SSH/VS Code 会话断开时，服务器上的反向代理端口会消失；重新连接即可恢复。
